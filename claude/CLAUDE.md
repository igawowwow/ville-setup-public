# ヴィレグループ 全社共通ルール（Claude Code）

このファイルは `~/.claude/CLAUDE.md` に配置され、**全プロジェクトに適用**される。
プロジェクト固有のルールは各リポの `CLAUDE.md` に書く（そちらが優先）。

## コミュニケーション
- 日本語・カジュアル・簡潔。結論ファースト。前置きと要約の繰り返しは不要。
- 推測で答えない。確認できていないことは「未確認」と明示する。
- できないことは正直に「できない」＋代替案。動かないものを動くように見せない。

## コード・リポジトリ
- 全プロジェクトGitHub管理。`main` に直接コミットしない。必ずブランチ → PR。
- コミットメッセージは日本語でOK。何を・なぜ変えたかを1行目に。
- `.env` / 認証鍵 / サービスアカウントJSON は**絶対にコミットしない**。
  疑わしいときは `git diff --staged` を人間の目で確認してから push。
- 依存追加は最小限。「これ入れないと無理か？」を先に考える。

## セキュリティ（全員必須）
- 顧客情報・従業員の個人情報を外部サービスへ貼らない（Claude Code の入力を含む）。
  必要なら氏名・住所・電話をマスクしてから扱う。
- 本番DBへの破壊的SQL（DELETE / DROP / TRUNCATE / WHERE なしの UPDATE）は必ず人間の承認を取る。
- 認証情報は会社のGoogleアカウント経由のGoogleパスワードマネージャーで管理。Slack・メール・ドキュメントに平文で置かない。

## 品質
- 「動いた」と報告する前に必ず実行して確認する。テストが落ちたら落ちたと言う。
- パフォーマンスは後回しにしない。重い処理をそのまま本番に出さない。
- UI は「PCに詳しくない人が初見で使えるか」を基準にする。

## 業務システムの当たり所
| やりたいこと | 使うもの |
|---|---|
| 顧客・案件管理 | bizcore-v2 |
| 補助金の検索・診断 | hojokin-agent / shindan-tool |
| 会計・月次PL | freee（レポートは自動配信） |
| 勤怠・労務 | 就業規則＋勤務不在ルール（社内ハンドブック） |
| 社内連絡 | Slack |

## 困ったら
- 環境が壊れた → ターミナルで `vg-update`（セットアップを再実行して修復）
- それでも直らない → Slack で管理者へ。**自己判断で OS 再インストールはしない**
